sven does not know what a flake is. The root kind declares an `out` sink with `merge`, and `sven.flake`
gives the flake's outputs. Each sink with an `out` key gives its part.


```nix title="modules/fleet.nix" {6,12}
# The `out` sink of the root is the flake: `sven.flake` gives it.
{ sven, ... }:
{
  sven.kinds.fleet = {
    spawns.host = _: sven.host;
    sinks.out.reduce = sven.lib.reduce.merge;
  };
  sven.kinds.host.sinks.services.out =
    { host, services, ... }:
    {
      services.${host.name} = services;
    };
  sven.fleet.main = { };
  sven.host.web = { };
  sven.host.db = { };
  sven.flake = { out, ... }: out;
}
```

## Read the outputs

The `out` arg is the flake itself, read lazily. An element can build on other outputs without `inputs.self`:


```nix title="modules/aspects.nix" {7}
{ sven, lib, ... }:
{
  sven.aspects.nginx = {
    at = sven.host.web;
    services = "nginx";
  };
  sven.aspects.postgres = {
    at = sven.host.db;
    services = "postgres";
  };
  # the `out` arg: an element reads the flake outputs, lazily. No `inputs.self`.
  sven.aspects.inventory = {
    at = sven.kinds.fleet;
    out =
      { out, ... }:
      {
        inventory = lib.concatLists (lib.attrValues out.services);
      };
  };
}
```

```nix title="result"
{
  inventory = [
    "postgres"
    "nginx"
  ];
  services = {
    db = [
      "postgres"
    ];
    web = [
      "nginx"
    ];
  };
}
```

## With or without flakes

`(import sven).lib.mkFlake module` gives the flake outputs. `(import sven).lib.eval module` gives every query,
and `flake` is one of them. `mkFlake m` is `(eval m).flake`.


:::note[Laziness closes the loop]
`inventory` reads `out` and gives to `out`. There is no fixpoint to run: Nix computes a value only when something reads it,
and `inventory` never reads itself.
:::
