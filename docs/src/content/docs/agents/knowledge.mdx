An agent with a knowledge store (a triple store such as quipu) can keep the fleet as a graph and query it with SPARQL.
`sven.lib.rdf.share r` gives the eval result as sorted N-Triples: scopes, kinds, parents, active aspects, every routed
element as a node with its origin, and errors. It adds a sha256 and a count.


```nix title="modules/hosts.nix"
{ sven, ... }:
{
  sven.environment.prod.domain = "example.com";
  sven.host.web.environment = sven.environment.prod;
  sven.host.db.environment = sven.environment.prod;
  sven.aspects.nginx = { at = sven.host.web; services = "nginx"; };
}
```

## Same fleet, same hash

The triples are sorted, and sven gives the same answer whatever the file order. So two revisions compare by hash first.
The docs check it: the files of this template, loaded in reverse order, give the same sha256.

A fleet can give its pack as a flake output:


```nix title="modules/pack.nix"
# The routing graph as a knowledge pack: sorted N-Triples with a sha256. Same fleet, same hash, any file order.
{ sven, ... }:
{
  sven.aspects.pack = {
    at = sven.kinds.fleet;
    out.rdfPack = removeAttrs (sven.lib.rdf.share { graph = sven.lib.graph; active = { }; errors = [ ]; }) [ "ntriples" ];
  };
}
```

## Shapes

`sven.lib.rdf.shacl r` gives SHACL shapes from the schema: one node shape per kind with scopes, `sven:name` required,
`sven:parent` of the spawning kind, each field at most once, and `sh:class` for ref fields.


```turtle
@prefix sh: <http://www.w3.org/ns/shacl#> .
@prefix xsd: <http://www.w3.org/2001/XMLSchema#> .
@prefix rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#> .

<https://sven.dev/fleet/kind/fleet> a sh:NodeShape ;
  sh:targetClass <https://sven.dev/fleet/kind/fleet> ;
  sh:property [ sh:path <https://sven.dev/fleet/sven/name> ; sh:minCount 1 ; sh:maxCount 1 ; sh:datatype xsd:string ; ] ;
  sh:property [ sh:path <https://sven.dev/fleet/sven/parent> ; sh:maxCount 1 ; ] ;
  .

<https://sven.dev/fleet/kind/host> a sh:NodeShape ;
  sh:targetClass <https://sven.dev/fleet/kind/host> ;
  sh:property [ sh:path <https://sven.dev/fleet/sven/name> …
```

:::tip[One snapshot per revision]
Store each revision's pack under one snapshot key, replacing the last. The store keeps old ones readable by transaction,
so "what did the fleet look like before this change" is a query.
:::
